# TestPilotAI — Artifact for "Towards a Multidimensional Diagnostic Framework for Automated Test Quality Assessment"

This repository is the artifact accompanying the paper:

> **Towards a Multidimensional Diagnostic Framework for Automated Test Quality Assessment**
> Victor Alves (University of São Paulo), Carla Bezerra (Federal University of Ceará), Marcio Delamaro (University of São Paulo)
> SBES 2026, September 8–11, 2026, São Paulo, SP, Brazil.
>
> 📄 **Paper:** [`tqs_paper/paper.pdf`](tqs_paper/paper.pdf)

The paper introduces the **Test Quality Score (TQS)**, a multidimensional metric that scores automatically
generated unit tests by balancing a *Potential Vector* (positive attributes: edge cases, coverage, functional
coverage, assertion diversity) against a *Noise Vector* (penalties: syntax errors, test smells). TQS is
validated empirically against Mutation Score (MS) on 52 test suites generated by six LLMs under three
prompting strategies, over 17 HumanEval problems.

## How this repository is organized

| Path | Content | Role |
|---|---|---|
| [`tqs_paper/`](tqs_paper/) | Frozen dataset, TQS computation scripts, mutation/coverage pipeline, analysis notebook, generated figures | **Primary artifact.** 100% of the metric described in the paper was computed and validated here. See [`tqs_paper/README.md`](tqs_paper/README.md) for full documentation, requirements, and step-by-step reproduction instructions. |
| [`process/`](process/) | Flask web app + LLM-orchestration code used to generate the raw test suites in `tqs_paper/tests_final/` | Auxiliary/provenance. Not required to reproduce the paper's results. See [`process/README.md`](process/README.md). |
| `README.md`, `LICENSE` | This file and the repository license | — |

If you only want to check the paper's claims (RQ1–RQ3, Figures 2–5, correlation and diagnostic statistics),
you only need **`tqs_paper/`** — go straight to [`tqs_paper/README.md`](tqs_paper/README.md).

## Requirements

The two subfolders have independent, non-overlapping dependencies (see each subfolder's own
`requirements.txt` and README for full details):

- **`tqs_paper/`** (data analysis): Python ≥ 3.10, pandas, numpy, matplotlib, seaborn, scipy, scikit-learn,
  jupyter. No GPU or special hardware required; runs on Linux/macOS/Windows.
- **`process/`** (test-generation pipeline, optional): Python ≥ 3.10, Flask, [Ollama](https://ollama.com/)
  with the six LLMs used in the study, ≥16 GB RAM recommended for local 7–13B models.

## Installation

```bash
cd tqs_paper
pip install -r requirements.txt
```

**1. Recompute the TQS score from the stored attributes** (validates the metric implementation, does not
touch the canonical dataset):

```bash
python calc_tqs.py
```

Expected output (confirms the installation works):

```
TQS calculado para 51 entradas
Min TQS: 1.5000
Max TQS: 7.0000
Média TQS: 4.5532
```

**2. Reproduce the corpus distribution figure (Figure 2 of the paper):**

```bash
python fig_corpus_distribution.py
```

Expected output: `Salvo: fig_corpus_distribution.pdf / .png` and two image files written to `tqs_paper/` —
compare them against the copies already committed there.

**3. Reproduce the correlation, ROC/AUC, and diagnostic analyses (RQ1–RQ3, Figures 3–5):**

```bash
jupyter nbconvert --to notebook --execute --inplace dashboard_TQS_correlation.ipynb
```

or open `dashboard_TQS_correlation.ipynb` in Jupyter/VS Code and run all cells. The first cell should print:

```
Dataset: n=51 entradas
TQS  — [1.50, 7.00]   média=4.55
MS   — [0.000, 1.000]  média=0.833

   Métrica   Valor  p-value  Significativo (α=0.05)
0  Pearson r  0.4756   0.0004                    True
1 Spearman ρ  0.2795   0.0470                    True
2  Kendall τ  0.2356   0.0323                    True
```

These match the Pearson r = 0.476 (p = 0.0004), Spearman ρ = 0.279 (p = 0.047), and Kendall τ = 0.236
(p = 0.032) reported for RQ1 in the paper. The remaining cells reproduce the ROC/AUC analysis for RQ2
(AUC = 0.666, Figure 4) and the diagnostic/percentage breakdown for RQ3 (Figures 5–6, e.g. 71.4% of
high-MS tests carry at least one quality issue invisible to mutation score).

**4. (Optional, Linux/WSL only) Re-run mutation testing and coverage collection from scratch:**

```bash
pip install pyproteum   # inside your Linux/WSL environment
python rodar_pyproteum.py
python run_coverage.py
```

This regenerates the raw attributes that feed step 1 above; it is not needed to verify the paper's reported
numbers, since those are already frozen in `tqs_paper/final_dataset_tqs.json`. Full details on the dataset
schema, pipeline order, hardware/OS requirements, and data provenance are in
[`tqs_paper/README.md`](tqs_paper/README.md).

Instructions for re-running the LLM test-generation pipeline that produced the raw test suites (optional,
not needed to reproduce the paper's results) are in [`process/README.md`](process/README.md).
