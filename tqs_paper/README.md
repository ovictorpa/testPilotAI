# TQS Empirical Study — Artifact

This folder contains the **complete empirical dataset, pipeline, and analysis code** used to compute the
**Test Quality Score (TQS)** and validate it against Mutation Score (MS), as reported in the paper:

> **Towards a Multidimensional Diagnostic Framework for Automated Test Quality Assessment**
> Victor Alves, Carla Bezerra, Marcio Delamaro — SBES 2026, September 8–11, 2026, São Paulo, SP, Brazil.
> 📄 Paper PDF: [`paper.pdf`](paper.pdf)

Every number, table, and figure in the paper's Results section (RQ1–RQ3) is reproducible from the contents
of this directory. This is the primary artifact of the submission — see the repository [root README](../README.md)
for how this folder relates to the rest of the project.

## What is TQS?

TQS is a composite metric that scores a generated unit test suite as the difference between a **Potential
Vector** (rewards for edge cases, coverage, functional coverage, assertion diversity) and a **Noise Vector**
(penalties for syntax errors and test smells). See Section 3 of the paper for the full formalization and
Table 1 for the attribute weights used in this study.

### Pipeline order

The four executable stages were run in this order to go from raw test suites to the paper's results. Stages
1–2 are **optional to re-run** (their outputs are already baked into `final_dataset_tqs.json`); stage 3 and
the analysis scripts are the ones needed to reproduce the reported numbers and figures.

1. `rodar_pyproteum.py` — for each `test_<LLM>_<prompt>.py` in `tests_final/`, runs the test against the
   production code (baseline check), then mutates the production code with **pyproteum** and measures the
   Mutation Score. Writes `mutation_scores_pyproteum.json` (not shipped, since it is fully superseded by
   `final_dataset_tqs.json`). Requires Linux/WSL (see Requirements).
2. `run_coverage.py` — re-runs each passing test suite with `pytest --cov` to (re)compute statement coverage
   and merges it back into the mutation-score JSON.
3. `calc_tqs.py` — reads the attributes collected above (execution status, coverage, functional coverage,
   assertion diversity, edge cases, test smells) and computes the final TQS per Equation 1 of the paper. This
   is the reference implementation of the metric.
4. `fig_corpus_distribution.py` and `dashboard_TQS_correlation.ipynb` — read the frozen
   `final_dataset_tqs.json` and produce every statistic and figure reported in the Results section (Pearson/
   Spearman/Kendall correlation, OLS regression, ROC/AUC, and the diagnostic/percentage analyses for RQ1–RQ3).

Test smell detection (attribute A6) was performed separately with the external [PyNose](https://pypi.org/project/pynose/)
tool, as described in Section 4.2.3 of the paper; its output is already merged into `final_dataset_tqs.json`
(field `test_smells`) and is not re-run by these scripts.

### Dataset schema (`final_dataset_tqs.json` / `.csv`)

Each of the 51–52 valid entries (one per LLM × prompting-strategy × HumanEval task combination that executed
without errors) has the following fields:

| Field | Description |
|---|---|
| `task_id` | HumanEval problem id (matches `tests_final/task_<id>/`) |
| `llm` | Model that generated the test suite (LLaMA3, CodeLLaMA, Gemma, CodeGemma, WizardCoder) |
| `prompt_type` | Prompting strategy: `zero_shot`, `few_shot`, or `cot` (chain-of-thought) |
| `baseline_passed` | Whether the suite executed successfully against the production code |
| `mutation_score` | Mutation Score (MS), from pyproteum — used as the external validation variable |
| `coverage` | Statement coverage ratio (0–1), from coverage.py |
| `functions_tested` / `total_functions` | Used to compute functional coverage (A3) |
| `assert_types` | List of distinct `assert*` methods used (drives A4, assertion diversity) |
| `edge_case_found` | Whether the suite exercises boundary values (0, "", None, negatives, …) — A1 |
| `test_smells` | List of test smells detected by PyNose (e.g. `magic_number`, `redundant_assertion`) — A6 |
| `tqs` | Final Test Quality Score (Equation 1: `VP − VN`) |

## Requirements

- **Python ≥ 3.10** (developed and tested on 3.12)
- Packages listed in [`requirements.txt`](requirements.txt) — install with `pip install -r requirements.txt`
- To *view* the results and regenerate the figures/statistics (steps 3–4 above): no OS restrictions, works
  on Windows/Linux/macOS.
- To *re-run mutation testing from scratch* (`rodar_pyproteum.py`, optional): a Linux environment is
  required, since [pyproteum](https://pypi.org/project/pyproteum/) is Linux-only. On Windows, the script
  automatically re-invokes itself under **WSL** (`wsl.exe`); a working WSL installation with Python 3 and
  `pip install pyproteum` inside it is required for that path only.
- Hardware: no GPU or special hardware needed. The corpus is small (52 test suites, 17 tasks); the full
  pipeline (including mutation testing) runs on a laptop in a few minutes. No LLM inference happens in this
  folder — that already happened upstream (see [`../process/`](../process/)) and its output is frozen here.

## Installation / Quick start

```bash
cd tqs_paper
pip install -r requirements.txt
```

**1. Recompute the TQS score from the stored attributes** (validates the metric implementation, does not
touch the canonical dataset):

```bash
python calc_tqs.py
```

Expected output (confirms the installation works):

```
TQS calculado para 51 entradas
Min TQS: 1.5000
Max TQS: 7.0000
Média TQS: 4.5532
```

**2. Reproduce the corpus distribution figure (Figure 2 of the paper):**

```bash
python fig_corpus_distribution.py
```

Expected output: `Salvo: fig_corpus_distribution.pdf / .png` and two image files written to this folder —
compare them against the copies already committed here.

**3. Reproduce the correlation, ROC/AUC, and diagnostic analyses (RQ1–RQ3, Figures 3–5):**

```bash
jupyter nbconvert --to notebook --execute --inplace dashboard_TQS_correlation.ipynb
```

or open `dashboard_TQS_correlation.ipynb` in Jupyter/VS Code and run all cells. The first cell should print:

```
Dataset: n=51 entradas
TQS  — [1.50, 7.00]   média=4.55
MS   — [0.000, 1.000]  média=0.833

   Métrica   Valor  p-value  Significativo (α=0.05)
0  Pearson r  0.4756   0.0004                    True
1 Spearman ρ  0.2795   0.0470                    True
2  Kendall τ  0.2356   0.0323                    True
```

These match the Pearson r = 0.476 (p = 0.0004), Spearman ρ = 0.279 (p = 0.047), and Kendall τ = 0.236
(p = 0.032) reported for RQ1 in the paper.

**4. (Optional, Linux/WSL only) Re-run mutation testing from scratch:**

```bash
pip install pyproteum   # inside your Linux/WSL environment
python rodar_pyproteum.py
python run_coverage.py
```

## Data storage and ethical/legal statement

- **Size:** the full corpus (`tests_final/`) plus datasets total a few megabytes; no special storage
  requirements.
- **Provenance:** the production code under test is a sample extracted from
  [HumanEval](https://github.com/openai/human-eval) (OpenAI, MIT-licensed, publicly available benchmark).
  The test suites in `tests_final/` were generated by open-source/local LLMs (LLaMA 3, CodeLLaMA, Gemma,
  CodeGemma, WizardCoder) run via [Ollama](https://ollama.com/); no proprietary model output is redistributed.
- **Personal/sensitive data:** none. The dataset contains only source code and automatically computed
  quality metrics; it involves no human subjects, personal data, or sensitive information.
- **License:** this folder is covered by the [repository LICENSE](../LICENSE) (MIT).

## Relationship to the rest of the repository

This directory is self-contained and is the object of the "Available"/"Reusable" open-science badges for
this submission. The [`../process/`](../process/) folder holds the auxiliary Flask application and LLM
orchestration code that *generated* the raw test suites in `tests_final/` in the first place; it is kept for
provenance/transparency but is not required to reproduce the paper's reported results — everything needed
for that lives here, anchored on the frozen `final_dataset_tqs.json`.
